# ADR 0008 · 放弃精灵图集路线，长期用 Canvas 代码绘制

- 状态：Accepted
- 日期：2026-05-23
- 范围：替换 PRD §2.1（"画风"）、§3.1.1（"运动逻辑"渲染部分）、整个 §6（AI 精灵图集生产 SOP）
- 来源：Cipher 体验后的判定。占位 SVG 风太块状不喜欢；真精灵图集生产复杂且角色一致性靠运气

## 决策

**长期方向**：水豚永远用 Canvas 2D 代码绘制，不再走"AI 出图 + 后处理"的精灵图集路线。

实现位置：`src/renderer/placeholder_capybara.js`（文件名保留为 placeholder 是历史包袱，含义上它现在是**唯一**渲染路径）。

为了让代码画法在视觉上**不像**廉价占位，新版用到的技术：

- **径向渐变**给身体和头打体积光
- **多层低 alpha 椭圆叠加**模拟 "fur halo" 柔边（替代 Canvas filter blur，跨平台行为一致）
- **地面径向阴影**跟随动作（睡觉变大、跳跃跟着抖）
- **贝塞尔曲线**画耳、嘴、尾巴的弧线
- **眼睛多型态**：normal / sparkle（带双高光）/ closed_smile（弧）/ half（半闭）
- **每动作独立 pose**（10 个动作 × 各自的姿态调整）+ **小动画**（眨眼 / 呼吸 / 走路上下 / 尾巴摇 / 睡觉 Z 字 / 惊讶感叹号 / 喷嚏粒子 / 难过眼泪）

## 为什么不走 SVG

用户原话"SVG 那种色块很丑"——本质上是因为：
- 几何形状 + 平涂色 → 即使是矢量也只是"色块"
- 没有梯度（gradients are possible but feel forced in SVG）
- 没有时间维度的微动（SVG 加动画要写 SMIL 或 JS 控）

Canvas 2D 同时给我们：高频帧动画 + 渐变 + 程序化粒子 + 时间一致的微动表现。

## 为什么不走 Live2D / Spine

CLAUDE.md §7 锁定 "Canvas 2D"，主要原因：

- 零额外资源依赖（Live2D 要 SDK + 模型文件）
- 零美术依赖（没人愿意为长尾开源项目画 Live2D）
- CPU 友好，符合 PRD §8.2 idle < 1% 预算

## 为什么不直接用真精灵图集（AI 出图后处理）

PRD §6 整套流程现在归档：

- 角色一致性需要 4-6 小时手挑筛选（PRD §6.6 自己也承认）
- AI 出图永远会有 1-3 px 漂移，靠 Aseprite 手修代价更大
- 加新动作 = 重新生成+筛选+对齐，长期成本高
- 程序化绘制改一个动作 = 改 `computePose` 里几个数字

精灵图集对**有美术团队**的桌宠项目仍然合理；对**作者本人为第一用户**的长期开源项目，代码绘制的边际成本远低。

## 影响

- **PRD §6 整章作废**：保留作为历史，不再执行
- **`src/assets/sprites/` 目录意义改变**：以前是"放真精灵图的地方"，现在是"如果某天想 A/B 真精灵 vs 代码"的可选实验目录，里面已有的 PNG 不会被读取（`PREFER_CODE_DRAWN = true` 直接跳过加载）
- **`scripts/gen_sprites.py`（计划中的精灵后处理脚本）取消**：不再需要写
- **M1 里程碑重定义**：原本是"精灵图集生产"，现在改成"代码绘制渲染器达到产品质量"，本 ADR 即视为 M1 完成

## 后续优化（可选）

代码绘制随时可以再加东西，几乎无成本：

- **季节皮肤**：调色板换一组（雪天的水豚颜色更冷）
- **生日装饰**：在 overlay 层加纸帽 / 蛋糕
- **基于音频的口型**：talk 动作配合外部音频幅度（M6 之后做 TTS 时一起）
- **更多 idle 微动**：随机偶发的"挠耳朵"、"看脚下"、"打个小哈欠"（用 t 取模 + 概率门控）
